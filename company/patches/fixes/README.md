# fixes（缺陷修复补丁）

修官方代码里的**行为缺陷**——不是换皮，也不是新增能力，而是官方现有逻辑本身有问题、在用户界面上能被看见。

## 与另外两个目录的区别

| 目录 | 放什么 | 是否改动官方逻辑 |
| --- | --- | --- |
| `branding/` | 换皮（颜色、logo 位置） | 否 |
| `extensions/` | 新增能力（插件、协议适配） | 否，只挂新东西 |
| `fixes/` | 修官方现有逻辑的缺陷 | **是** |

`fixes/` 触碰的是官方既有逻辑，风险高于前两类，因此每个补丁必须同时满足：

1. 有可复现的现象描述（谁、在哪个页面、看到什么）。
2. 有对应的自动化测试，且测试在修复前会失败、修复后通过。
3. 不涉及计费、渠道路由、数据库表结构。
4. 在 `PATCHES.md` 登记编号，`manifest.json` 同步一条。

以上任一条做不到，就不要往这里放，先回到「前端能否解决」再判断一次。
