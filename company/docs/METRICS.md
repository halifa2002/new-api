# 统计口径说明

对应领导 md 4.2 D：「需要明确时间范围、时区、统计口径和分页规则」。

这份文件定义控制台「用量统计」「消费记录」里每个数字是怎么算出来的。**改口径必须同时改这里**，否则算 bug。

## 1. 时间

| 项目 | 规则 |
| --- | --- |
| 存储 | 后端日志表 `created_at` 是 Unix 秒（绝对时间，不带时区） |
| 切分 | 一律按**使用者浏览器的本地时区**。北京用户从 0 点切日，换到别的时区看边界会跟着变 |
| 今天 | 本机 0 点 → 现在 |
| 近 7 天 / 近 30 天 | 现在往前推 7 / 30 个 24 小时，**滚动窗口**，不是自然周 / 自然月 |
| 全部 | 不带时间条件 |

已知边界情况：同一账号在两个时区查看，日界线不同，同一天的数字会不一样。这是按设备时区切分的必然结果，不是 bug。

## 2. 金额

- 后端只存 quota（整数），不存金额。
- 前端换算：**金额 = quota ÷ quota_per_unit × usd_exchange_rate**
- 两个参数都从 `/api/status` 实时取，不写死。当前：`quota_per_unit = 500000`，`usd_exchange_rate = 7.3`。
- 后台改了换算参数，页面数字随之变化；**历史记录不回溯**。

## 3. 成功与失败

- 成功调用 = 消费日志（`type = 2`），`quota` 是实际扣费。
- 失败调用 = 错误日志（`type = 5`），**不扣费**。
- 成功率 = 成功条数 ÷（成功条数 + 失败条数），限定在所选区间内；两个数都取后端分页返回的 `total`，不是前端把列表加起来。
- 日志类型全表：0 未知 / 1 充值 / 2 消费 / 3 管理 / 4 系统 / 5 错误 / 6 退款 / 7 登录。用量页只看 2 和 5。

## 4. 分页与采样上限

- 调用明细：每页 20 条，按 `page` + `page_size` 请求，以响应里的 `total` 为准。
- 每日趋势、分布统计：官方没有「按天/按模型聚合」的接口，前端只能取一段明细自己分组，**上限 500 条**。
- 超过 500 条时，趋势图只含最近 500 条，页面会显示「超出部分未计入」；上方的汇总数字仍按后端 `total` 统计。
- 结论：**趋势图用来看形状，不要用来对总账**。

## 5. 数据来源

| 用途 | 接口 |
| --- | --- |
| 区间汇总（次数、Token、消费） | `GET /api/log/self/stat` |
| 调用明细、按模型/按密钥分布 | `GET /api/log/self` |

不使用本地缓存、不做前端估算、不直连数据库。

## 6. 什么时候必须更新这份文件

改时间区间算法、改金额换算、改成功/失败判定、改分页大小、改采样上限——任何一项变了都要同步这里，并在提交信息里写明。
